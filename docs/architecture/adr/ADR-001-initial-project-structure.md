# ADR-001：从单 Maven 项目和纯 Java 单体开始

- **状态：** 已采纳
- **日期：** 2026-09-25

## 背景

项目需要承载多个 Java 学习阶段，最终可能发展为交易、电商与风控系统。当前优先目标是理解 Java，而不是先搭建基础设施或服务集群。

## 决策

- 使用 Java 17、Maven 单项目和 JUnit 5。
- Stage 1 的业务代码使用纯 Java；只建有真实内容的 application、domain 和 lab 包。
- 当前业务用构造参数传入内存商品目录；领域代码不依赖 Spring、数据库或消息中间件。
- 学习实验与业务路径分开放置，实验目的和结论写在 `docs/learning/lab/`。
- 以 ADR 记录重要技术和结构选择；未来技术依赖在对应学习阶段再加入。

## 考虑过的方案

1. **一开始就建多 Maven 模块或微服务：** 能模拟目标形态，但会引入构建、通信和部署概念，遮住 Java 基础。
2. **一开始使用 Spring Boot + 数据库：** 业务演示更接近生产，但容器、框架和持久化细节会抢占当前学习重点。
3. **当前单体，按学习问题演进：** 构建简单，单测可直接反馈领域规则，也保留后续划分模块和替换适配器的空间。选择此方案。

## 后果

- 当前仓库不会展示真正的数据库持久化、跨进程调用、事务一致性或生产级并发安全。
- `Map` 和学习实验只服务当前阶段；需要并发或持久化保证时，必须重新评估设计。
- 服务拆分前先形成可测试的领域边界，再通过 ADR 说明拆分理由、通信方式和失败处理。

## 后续复核

进入 Stage 4 时复核是否引入 Spring Boot；进入 Stage 5 时分别记录数据库、缓存和消息队列选择；引入多进程或模块时记录依赖方向及服务边界。
